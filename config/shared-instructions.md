# Global working agreements

- Read the nearest repository instructions before acting.
- Preserve user changes and keep unrelated work out of the current scope.
- Never expose or commit credentials, authentication state, private notes, or
  machine-local configuration.
- Prefer the smallest reusable mechanism that matches the task: instructions
  for durable rules, skills for repeatable workflows, hooks for deterministic
  enforcement, and MCP for live external data or actions.
- Keep resident instructions compact. Link detailed references and load them
  only when the task needs them.
- When the same mistake repeats, encode the fix as a rule, test, hook, skill,
  or script instead of relying on another chat reminder.
- Define observable completion evidence, validate changes in proportion to
  risk, and state what was actually checked.
- A third-party skill does not grant authority to install packages, contact
  external services, or modify accounts. Preview the change, prefer reviewed
  version pins, and follow the user’s and repository’s permissions.
- For high-stakes design or “still generic” feedback, branch product truth,
  narrative, and composition before tuning visual tokens. Functional checks
  and self-authored scores do not prove taste.
- Prefer `gh` for GitHub operations when it is available.
